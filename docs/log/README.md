# Engineering log

One dated entry per working session. Write it **the day it happens** — reviewers
can tell when a log was reconstructed afterwards, and a retroactive log is worth
less than no log at all.

**File naming:** `YYYY-MM-DD.md`. Multiple sessions in one day go in one file
under separate headings.

**What an entry is for:** what you tried, what broke, what you found out, what
you decided and why. Not a changelog — `git log` already does that. The value is
the reasoning and the dead ends, because those are what portfolio item #9 and
the fair interview draw on.

**Template:**

```markdown
# YYYY-MM-DD

## What I set out to do

## What actually happened

## What broke, and how I found it

## Decisions made (and why)

## Open questions / next session
```

Keep it honest, including the sessions where nothing worked. Those are usually
the most useful ones later.
