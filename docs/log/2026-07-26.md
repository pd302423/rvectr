## What broke, and how I found it

**The EasyMocap pipeline does not do motion capture.** This is the significant
finding of the session and it was not something I knew going in.

`backend/run_easymocap_videos2.py` has three steps. Step 1 calibrates cameras
from chessboard images — real. Step 2 runs MediaPipe across both camera views and
writes per-frame 2D keypoint annotations — real. Step 3 was named
`fit_easymocap_3d_smpl()`, its docstring said "Runs EasyMocap multi-view 3D
triangulation and SMPL/SMPL-X body fitting", and it printed that same claim to
the console.

It does none of that. It loads the dataset, uses it *only* for `len(dataset)` to
get a frame count, and then writes hardcoded joint angles into the 72-parameter
pose vector:

```python
progress = np.sin(np.pi * t)
raw_poses[f, 12] = 1.45 * progress   # Left Knee
raw_poses[f, 15] = 1.45 * progress   # Right Knee
```

The keypoints from step 2 are never read. No triangulation happens. No fitting
happens. The output is a hand-authored sine-wave animation that borrows nothing
from the recorded video except its length.

Everything downstream inherits this: `videos2/obj_sequence/`,
`squat_multiview_animated.glb`, `squat_3d_mesh.glb`, `squat_vertices_anim.npy`.
All of it is animation, not measurement. These are the assets that
`WORKSPACE_SUMMARY.md` described as multi-view capture results.

**How it surfaced:** I was tracing the Gaussian-vs-Savitzky–Golay filter question
from the critique and read the surrounding function to check what was being
filtered. The filter turned out to be smoothing hand-written numbers.

**A correction to my own critique.** Finding 7 in `critical_analysis.md`
attributed Gaussian filtering to `zero_drift_perfect_smpl_builder.py`, citing
`WORKSPACE_SUMMARY.md:58`. That was wrong — that script already used
`savgol_filter`. The documentation was inaccurate, not the code. The real
Gaussian usages were in `run_easymocap_videos2.py` and
`recalibrate_and_reconstruct_3d.py`. Lesson: verify against source, not against
the project's own docs. The docs were wrong about the code more than once today.

## Decisions made (and why)

**Submodule work committed locally, not pushed.** 4,467 uncommitted files in
EasyMocap. Committed the ~400K of irreplaceable source and calibration
(`intri.yml`/`extri.yml`, `export_glb.py`, configs, annotations, source video)
and gitignored ~315MB of regenerable output. Bundles written to
`~/rvectr-backups/`. Still on one disk — forking and pushing needs my GitHub
auth and is the next action.

**Fabricated accuracy figures deleted.** The `0.8°/1.5°/1.6°/2.4°` MAE numbers
and their accuracy percentages appeared in three documents, including a
goniometer comparison table in the slide deck with invented per-measurement
pairs. Nothing produced them. Replaced with explicit "not yet measured"
statements. A CI check now fails the build if they reappear.

**H₃ (robotics teleoperation) removed from hypotheses.** No IK code, no ROS2, no
robot, no simulation exists. It was an aspiration sitting where a tested
hypothesis belongs. H₂ softened from "eliminate self-occlusion" to a bounded,
falsifiable reduction.

**Relicensed research/non-commercial.** The README claimed MIT while EasyMocap
permits non-profit use only and requires modifications stay open-source. There
was no LICENSE file at all. Added one that states plainly why it cannot be MIT.

**Savitzky–Golay replaces Gaussian** in the two places Gaussian was actually
used. Gaussian attenuates local extrema, peak joint angles are what this project
measures, and the attenuation worsens with speed — it would have manufactured a
velocity-dependent error trend from a perfect estimator. Also fixed a hand-rolled
convolution whose comment claimed reflect padding while `np.convolve(mode='same')`
actually zero-pads, dragging the first and last few frames toward the origin.

**"Clinical" removed** from README and WORKSPACE_SUMMARY. Nothing here is
validated against a reference standard; the word invites a question I cannot
answer.
